# AI 사주 상담 웹 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로그인 없이, 만세력 모듈이 확정한 사주만으로 연애·성공/진로·종합 상담을 두 가지 말투로 보여주는 모바일 우선 웹을 만든다.

**Architecture:** 브라우저의 계산 라이브러리 접근은 없다. 출생 정보는 `POST /api/chart`와 `POST /api/reading`에서만 `lunar-javascript`로 다시 계산한다. 해석은 서버의 OpenAI Structured Outputs가 맡고, 화면의 간지·오행·십성은 모델 문장이 아니라 서버 차트에서 그린다. 상담 내용은 서버에 저장하지 않고 이 탭의 `sessionStorage`에만 둔다.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript, Tailwind CSS 3, Vitest, Zod, `lunar-javascript` 1.7.x, `openai` Node SDK (`chat.completions.parse` + `zodResponseFormat`).

**Spec:** `saju_service_product_plan.md`, `saju_web_design_plan.md`

## Global Constraints

- 서비스 형태: 모바일 우선 반응형 웹. MVP에서 회원가입, 결제, 상담 기록의 서버 저장, 궁합, 타로, 작명, 건강·투자 운세, 푸시, 커뮤니티, 상담가 비교 점수는 만들지 않는다.
- 핵심 원칙: 계산은 결정론적 만세력 모듈, 해석과 표현은 OpenAI API. AI는 원국·오행·십성·대운·세운을 추측하거나 재계산하지 않는다.
- 주제는 `love`(연애), `career`(성공·진로), `general`(종합) 세 가지. 상담가는 `clear`(명료한 상담가), `empathetic`(공감형 상담가). 두 스타일은 같은 차트와 지식, 다른 말투만 쓴다.
- 결과 화면의 스타일 전환은 만들지 않는다.
- 응답 필드: `summary`, `saju_evidence`, `interpretation`, `actions`(1~3개), `limitations`, `follow_up_question`.
- API 키는 `OPENAI_API_KEY` 서버 환경 변수. 기본 모델은 `OPENAI_MODEL`이며 없으면 `gpt-4o-mini`. 키, 요청 원문, API 오류 본문은 브라우저와 로그에 넣지 않는다.
- 성별은 받지 않는다. 대운은 계산하지 않고, 그 사실을 `uncertainties`에 넣는다.
- 계산 정책: 월주는 절기 기준(`lunar-javascript`의 EightChar). 일주는 자정에 바뀐다(`setSect(2)`). 23:00–23:59의 일주는 그 양력 날짜를 유지하고 시주는 자시다. 시간 미상은 시주를 만들지 않는다. 시간대는 `Asia/Seoul`(한국 표준시)만 쓰며 진태양시 보정은 하지 않는다. 지원 연도는 1900–2099.
- 색: 배경 `#F7F5EF`, 본문 `#243447`, 주 포인트 `#2E7774`, 보조 `#A98BB8`, 안내 배경 `#EAF3F1`. 본문 16px 이상, 제목 24–32px. 카드 모서리 16px, 얕은 테두리, 과한 그림자 없음. 한글 산세리프는 Pretendard.
- 선택 상태는 색만으로 나타내지 않는다. 체크와 "선택됨" 텍스트를 함께 쓴다. 모바일 주요 버튼은 화면 하단에 고정하고 터치 높이는 48px 이상.
- 화면 문구에 점수, 적중률, 운명 확정, "반드시", "무조건", "틀림없이"를 쓰지 않는다. 결과 안내 문장은 "이 해석은 전통 명리 관점의 참고 정보입니다."
- 로그에는 주제, 상담가, 처리 시간, 오류 종류만 남긴다. 생년월일, 시각, 질문, 응답 본문은 로그에 남기지 않는다.

## Review Focus

아래 다섯 가지는 스펙이 화면 문구로만 말하고 테스트가 빠지기 쉬운 입력이다. 각 항목의 테스트는 해당 과제에 들어 있다.

1. 그 해에 없는 윤달(2023년 윤5월)은 조용히 다른 달로 계산하지 않고, 달을 고치라는 검증 오류를 반환한다.
2. 양력 1988-02-15 23:30의 일주는 같은 날 22:30의 일주 `경자`와 같고, 시주는 `무자`다. 23시대에 다음 날 일주로 넘기지 않는다.
3. 출생 시각 미상은 시주 기둥을 결과에 넣지 않고, `uncertainties`에 시주를 제외했다는 문장을 넣는다. 라이브러리 호출용 12:00은 밖으로 나가지 않는다.
4. 요청 본문에 기둥이나 이전 답변을 섞어도 프롬프트의 사주 JSON은 서버가 방금 계산한 차트다. 클라이언트가 보낸 간지는 읽지 않는다.
5. 모델이 "반드시" 같은 단정을 반환하거나 API가 예외를 던지면, 사용자에게는 입력 유지와 재시도만 안내하고 오류 원문과 키는 보여 주지 않는다.

## 구현 전에 고정한 결정

스펙이 프레임워크와 자시 경계를 지정하지 않아 아래를 제품 정책으로 고정한다.

- 만세력은 직접 구현하지 않고 `lunar-javascript`에 맡긴다. 골든 케이스는 이 라이브러리 공개 테스트의 네 시각이다. 출시 전에 같은 네 시각을 팀이 신뢰하는 만세력과 한 번 대조한다.
- 윤달은 라이브러리 규칙대로 음수 월이다. 2023년 윤달은 2월이다.
- 지역 목록으로 진태양시를 흉내 내지 않는다. 시간대 선택은 "한국 표준시 (Asia/Seoul)" 하나이고, 화면은 지역 보정 없음을 미리 말한다.
- 후속 질문은 같은 출생 정보로 서버가 차트를 다시 계산한다. 이전 요약은 신뢰하지 않는 사용자 글로만 붙인다.

import { expect, it } from "vitest";
import { calculate } from "../../lib/saju/calculate";

const solar = {
  calendar: "solar" as const,
  isLeapMonth: false,
  timeKnown: true,
};

it("matches the library fixture 2005-12-23 08:37", () => {
  const chart = calculate({
    ...solar,
    year: 2005,
    month: 12,
    day: 23,
    hour: 8,
    minute: 37,
  });
  expect(chart.pillars.map((p) => p.ganzi)).toEqual(["을유", "무자", "신사", "임진"]);
  expect(chart.pillars[0]).toMatchObject({ elementGan: "목", elementZhi: "금" });
  expect(chart.pillars.map((p) => p.tenGodGan)).toEqual(["편재", "정인", "일간", "상관"]);
  expect(chart.dayMaster).toBe("신");
  expect(chart.policy).toMatchObject({
    sect: 2,
    dayBoundary: "midnight",
    timezone: "Asia/Seoul",
    trueSolarTime: false,
    hourIncluded: true,
  });
  expect(chart.uncertainties.join(" ")).toContain("대운은 계산하지 않습니다");
  expect(JSON.stringify(chart)).not.toContain("daewoon");
});

it("keeps the civil day pillar at 23:30", () => {
  const evening = calculate({
    ...solar,
    year: 1988,
    month: 2,
    day: 15,
    hour: 22,

- [ ] **Step 3: 계산 구현**

`lib/saju/calculate.ts`의 핵심은 아래다. 오행은 라이브러리 문자열을 쪼개지 말고 `elementOfStem` / `elementOfBranch`로 구한다. 지장간은 기둥에만 나열한다.

```ts
import { Lunar, Solar } from "lunar-javascript";
import { elementOfBranch, elementOfStem, koBranch, koStem, koTenGod } from "./maps";
import type { BirthInput, Pillar, SajuChart } from "./types";

const labels = ["연주", "월주", "일주", "시주"] as const;
const slots = ["Year", "Month", "Day", "Time"] as const;

function emptyCounts() {
  return { 목: 0, 화: 0, 토: 0, 금: 0, 수: 0 };
}

export function calculate(input: BirthInput): SajuChart {
  const hour = input.timeKnown ? input.hour ?? 12 : 12;
  const minute = input.timeKnown ? input.minute ?? 0 : 0;
  const lunar = input.calendar === "solar"
    ? Solar.fromYmdHms(input.year, input.month, input.day, hour, minute, 0).getLunar()
    : Lunar.fromYmdHms(
        input.year,
        input.isLeapMonth ? -input.month : input.month,
        input.day,
        hour,
        minute,
        0,
      );
  const eight = lunar.getEightChar();
  eight.setSect(2);

  const pillars: Pillar[] = slots.map((slot, index) => {
    const gan = eight[`get${slot}Gan`]();
    const zhi = eight[`get${slot}Zhi`]();
    return {
      label: labels[index],
      gan: koStem(gan),
      zhi: koBranch(zhi),
      ganzi: koStem(gan) + koBranch(zhi),
      elementGan: elementOfStem(gan),
      elementZhi: elementOfBranch(zhi),
      tenGodGan: koTenGod(eight[`get${slot}ShiShenGan`]()),
      hideGan: eight[`get${slot}HideGan`]().map((item: string) => koStem(item)),
    };
  });
  const visible = input.timeKnown ? pillars : pillars.slice(0, 3);
  const stem = emptyCounts();
  const branch = emptyCounts();
  for (const pillar of visible) {
    stem[pillar.elementGan] += 1;
    branch[pillar.elementZhi] += 1;
  }
  const uncertainties = ["성별을 입력받지 않아 대운은 계산하지 않습니다."];
  if (!input.timeKnown) {
    uncertainties.push("출생 시각을 몰라 시주를 계산하지 않았습니다.");
  }
  return {
    pillars: visible,
    dayMaster: visible[2].gan,
    elementCounts: { stem, branch },
    policy: {
      library: "lunar-javascript",
      monthRule: "solar-term",
      dayBoundary: "midnight",
      sect: 2,
      timezone: "Asia/Seoul",
      trueSolarTime: false,
      hourIncluded: input.timeKnown,
    },
    uncertainties,
  };
}
```
